# OS Resource Management Simulator

A terminal-based Operating Systems simulator built for the **B.Tech CSE Operating
Systems capstone project**. One menu drives four subsystems — CPU scheduling,
memory management, deadlock management and disk scheduling — computes the
standard metrics for each, compares the algorithms and produces charts, a
session log and a PDF report.

Everything is **Python 3 + Bash + Matplotlib + unittest**. No web framework, no
database, no external service: the algorithms are plain functions, so they can
be tested and explained line by line in a viva.

An optional **browser GUI** (`webapp/`, section 14) puts an interface on the same
modules for demonstrations — it uses only the Python standard library, so it adds
no dependency and the terminal application keeps working exactly as before.

---

## 1. What is implemented

| Subsystem | Algorithms | Metrics produced |
|---|---|---|
| CPU scheduling | FCFS, SJF, SRTF, Priority (non-preemptive), Round Robin | CT, TAT, WT, RT per process; averages; CPU utilisation; throughput; Gantt chart |
| Memory management | First Fit, Best Fit, Worst Fit | allocator table, internal + external fragmentation, stranded blocks, utilisation, memory layout |
| Deadlock management | Banker's safety, Banker's resource request, deadlock detection | safe sequence, Work trace, grant/refuse verdict with rollback, deadlocked process set |
| Disk scheduling | FCFS, SSTF, SCAN, C-SCAN | per-request seek arithmetic, total head movement, average movement, head path |

Both memory models are supported:

* **fixed partitions** — a process receives a whole partition, leaving internal
  fragmentation;
* **dynamic partitions** — holes are split, so internal fragmentation is zero and
  external fragmentation appears.

The integrated menu (option 5) runs all four subsystems on the sample datasets
and prints comparison tables, which is the evidence for the "performance
analysis" part of the rubric.

## 3. Setup

Requirements: **Python 3.9+** and, for charts/PDF, **Matplotlib**. Bash is used
only by the helper scripts; on Windows use **Git Bash** or **WSL**.

```bash
# 1) check the machine, create folders, byte-compile everything
./scripts/setup.sh

# optional: isolated environment with Matplotlib installed
./scripts/setup.sh --venv

# 2) run
./scripts/run.sh
```

Manual equivalent:

```bash
python3 -m pip install -r requirements.txt
python3 main.py
```

`matplotlib` is optional at runtime: without it every table still prints, the
chart functions return `None`, and the menu says charts are unavailable.

## 4. Using the menu

```
1) CPU Scheduling        FCFS, SJF, SRTF, Priority, Round Robin
2) Memory Management     First Fit, Best Fit, Worst Fit (fixed/dynamic)
3) Deadlock Management   Banker's safety, request algorithm, detection
4) Disk Scheduling       FCFS, SSTF, SCAN, C-SCAN
5) Performance Analysis  compare all four subsystems + charts
6) View Execution Logs   this session's entries and log file
7) Exit
```

For options 1–4 you can pick a sample dataset or type `c` to enter your own
data. The program validates every number and prints the reason when it rejects
one, so a wrong entry never ends the session.

* **CPU** — all five algorithms run on the chosen dataset; Round Robin's quantum
  is asked for (default 4).
* **Memory** — choose `fixed` or `dynamic`, then all three fit strategies run.
* **Deadlock** — prints the state, the safety trace and the detection trace, then
  optionally tests a `PID v1 v2 ...` request (a granted state can be adopted for
  further requests).
* **Disk** — choose the sweep direction `up`/`down` for SCAN/C-SCAN; all four
  algorithms run.

## 6. Formulas and conventions

### CPU

```
completion  = clock when the process's last slice ends
turnaround  = completion - arrival
waiting     = turnaround - burst
response    = first_cpu_time - arrival
span        = max(completion) - min(arrival)
utilisation = total burst / span * 100
throughput  = process count / span
```

The clock starts at the **first arrival**, so there is no artificial leading
`IDLE` segment and `sum(IDLE segments) == idle_time`. Ties are broken by earlier
arrival, then by input order. Priority **1 is the highest**.

### Memory

```
internal fragmentation = sum(partition size - process size)     (fixed model)
external fragmentation = free memory in blocks smaller than the smallest
                         rejected request (0 when nothing was rejected)
utilisation            = placed process bytes / total memory * 100
```

A request larger than total memory is reported separately and does not count as
external fragmentation, because no arrangement of holes could satisfy it.

### Deadlock

`Need = Max - Allocation` is always derived, never stored. A request above a
process's remaining Need is treated as **invalid input** (it violates the
maximum claim), not as a deadlock verdict. Detection uses `Request = Need` when
no explicit request matrix is supplied, and the UI states that source.

### Disk

`total movement` is the sum of |next - current| over the head path. SCAN and
C-SCAN travel to the disk edge and **that boundary travel is counted** (shown
with the note `boundary`). C-SCAN's fast return from the last cylinder to 0 is
recorded in `return_jump` and **not** counted; the charged value is printed
next to it, so either convention can be defended. Disk cylinders are
`0 .. disk_size - 1`.

## 12. Design decisions worth defending in a viva

1. **Pure algorithm modules.** Each algorithm takes data and returns a dataclass;
   it never prints or reads input. That is why 119 tests can call them directly,
   and why the menu, charts and PDF all reuse the same results.
2. **One metrics builder per module.** All five CPU algorithms share
   `_build_result`, so the formulas cannot drift between algorithms.
3. **Clock starts at the first arrival.** This keeps the Gantt honest:
   `sum(IDLE) == idle_time`, and utilisation is exactly busy time / span.
4. **Fragmentation is defined once.** Internal fragmentation only exists in the
   fixed model; external fragmentation is measured against the smallest
   *rejected* request. Best Fit's low fragmentation is visible in the numbers.
5. **Deadlock input errors are not verdicts.** A request above the maximum claim
   raises an error; a request that would leave the system unsafe is refused and
   rolled back. These are different things and the UI says so.
6. **C-SCAN jump is recorded separately.** Textbook keys disagree on whether the
   return is counted; the program prints both values instead of hiding a choice.
7. **Seeded, deterministic ordering.** No randomness anywhere, so every run of a
   dataset produces identical numbers — required for reproducible marks.

---

## 13. Limitations

* Time is an abstract integer unit; no real hardware timing is measured.
* The memory model is contiguous allocation only (no paging/segmentation).
* Deadlock handling covers multiple instances per resource type via Banker's
  algorithm; the wait-for graph is discussed but not drawn.
* Charts need Matplotlib; without it the report PDF cannot be generated.
* Screenshots are text transcripts; graphical screenshots must be captured on
  the machine where the project is demonstrated.
* The GUI is served from `localhost` for one user; it has no login, no HTTPS and
  no multi-user state (every run is computed from the request alone).

## 14. Optional web GUI (browser front end)

`webapp/` is a second front end for the **same** engines. It does not re-implement
any algorithm: the browser sends the dataset and options as JSON, `server.py`
calls `modules/...`, and the dataclass result is serialised back. Charts are drawn
in the browser with CSS and SVG from those numbers, so the GUI needs no extra
package beyond what the project already uses.

```bash
python3 webapp/server.py                 # http://127.0.0.1:8000
python3 webapp/server.py --port 9000     # another port
./scripts/run_gui.sh                     # same thing through Bash
python3 webapp/server.py --host 0.0.0.0  # reachable from another machine
```

Open the printed URL, choose a dataset (or expand *Edit the dataset* and paste
your own), pick an algorithm and press **Run**. Stop the server with `Ctrl+C`.

| View | What it shows |
|---|---|
| Overview | what the four subsystems do, and the commands for the terminal app |
| CPU Scheduling | metric tiles, Gantt chart, per-process table, comparison bars for all five algorithms |
| Memory | block map (allocated vs free), allocation table, fragmentation comparison for both models |
| Deadlock | Allocation / Max / Need matrix, safe sequence with Work trace, request verdict, detection trace |
| Disk | seek-path chart, movement table with boundary rows, totals and comparison |

**API** (all JSON, errors return HTTP 400 with a message):

| Endpoint | Body |
|---|---|
| `GET /api/meta` | — (datasets, algorithm names, default quantum) |
| `POST /api/cpu` | `{dataset}` or `{text}`, `algorithm`, `quantum` |
| `POST /api/memory` | `{dataset}` or `{text}`, `model` (`fixed`/`dynamic`), `algorithm` |
| `POST /api/deadlock` | `{dataset}` or `{text}`, `action` (`safety`/`request`/`detect`), `pid`, `request` |
| `POST /api/disk` | `{dataset}` or `{text}`, `algorithm`, `direction` |

Safety notes: dataset names are resolved inside `data/` only (a path such as
`../main.py` is rejected), the server binds to `127.0.0.1` by default, request
bodies are capped at 256 KB, and every input error is shown in the panel instead
of a traceback. It is a demonstration GUI, not a hardened web service.

Screenshots of the running page are in `screenshots/gui_*.png`.
